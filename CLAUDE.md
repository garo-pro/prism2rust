# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What this is

`prism2rust` provides **Rust bindings for [Prism](https://github.com/ethindp/prism)**,
the Platform-agnostic Reader Interface for Speech and Messages (a unified API
over screen readers and TTS engines). Upstream Prism is a C/C++23 library vendored
as a git submodule and pinned to a **stable release tag**.

## Repository layout

```
external/prism/            Vendored upstream (git submodule, pinned — see PRISM_PIN.toml)
PRISM_PIN.toml             Single source of truth for the pinned tag + commit
crates/
  prism-types/            Pure-Rust value types (errors, ids, feature flags). No linking.
  prism-sys/              Raw FFI. build.rs = "the bridge": bindgen + CMake native build.
  prism/                  Safe, idiomatic wrapper (Context, Backend, RegistryBuilder, log).
.claude/skills/           Maintenance skills: update-prism, update-bridge
.github/                  CI (ci.yml) + Dependabot (dependabot.yml)
docs/MAINTENANCE.md       How this project keeps itself current (self-maintaining model)
```

The three-crate split exists so **pure logic is testable without a C++ toolchain**:
`prism-types` compiles and tests on any machine; only `prism-sys`/`prism` need the
native library.

## The pin (reproducible clones)

- The exact commit every clone checks out is the **gitlink recorded in this
  superproject** (`git submodule status`). `.gitmodules` and `PRISM_PIN.toml`
  document it in human- and machine-readable form; all three must agree.
- Always pin a **stable release tag** (currently `v0.18.2`). Never track a moving
  branch. This is why Dependabot's `gitsubmodule` updater is deliberately disabled.
- After a fresh clone: `git submodule update --init --recursive`.

## The bridge

"The bridge" is the FFI layer in `crates/prism-sys` plus the safe mappings in
`crates/prism`. The raw bindings are generated by `bindgen` from
`external/prism/include/prism.h` and **checked in** at
`crates/prism-sys/src/bindings_pregenerated.rs` (so downstream builds need no
libclang). Regenerate them with the `update-bridge` skill — never edit that file
by hand.

## Maintenance workflows (use the skills)

- **Bump upstream Prism** → run the `update-prism` skill. It picks the newest
  *stable* tag, moves the submodule + `PRISM_PIN.toml` + `.gitmodules`, then hands
  off to `update-bridge`.
- **Reconcile API changes** → run the `update-bridge` skill. It regenerates the
  FFI, diffs the header, updates `prism-types`/safe wrappers for any API changes,
  and runs the full test suite.

See `docs/MAINTENANCE.md` for the full self-maintaining model.

## Testing policy — MANDATORY

**Everything must be tested. No change lands without tests.**

- Any new or changed behavior requires accompanying tests in the same change.
- Prefer **pure-Rust unit tests in `prism-types`** for logic that does not need
  the native library (error/id/flag mapping, conversions, invariants). These run
  everywhere and are the fast feedback loop.
- Anything touching the FFI or safe wrappers gets an **integration test in
  `crates/prism/tests/`** driven through a `CustomBackend` (see
  `custom_backend.rs`). This exercises the real C library deterministically with
  no screen reader present — register a mock backend, freeze a registry, run a
  `Context` against it.
- When you add a wrapper method, add a test that calls it and asserts the
  round-trip. When you add an error/id/flag, assert its value against the header.
- Keep the tree green: `cargo fmt --all --check`, `cargo clippy --workspace
  --all-targets -- -D warnings`, and the tests must all pass. CI enforces this.
- The `crates/prism/examples/` programs are compile-checked by clippy
  (`--all-targets`) and built in CI's native job; the portable `custom_backend`
  example is also *run* there. Keep them building when you change the API.

## Local commands

```bash
# Fast loop — no C++ toolchain needed:
PRISM_SYS_NO_NATIVE=1 cargo clippy --workspace --all-targets -- -D warnings
PRISM_SYS_NO_NATIVE=1 cargo fmt --all --check
cargo test -p prism-types --all-features

# Full build + integration tests (requires a C++23 compiler + CMake):
git submodule update --init --recursive
cargo test --workspace
```

`prism-sys` build-script environment variables (see `crates/prism-sys/README.md`):
`PRISM_SYS_NO_NATIVE`, `PRISM_LIB_DIR`, `PRISM_STATIC`, and (with `--features
bindgen`) `PRISM_SYS_UPDATE_PREGENERATED`.

## Conventions

- Edition 2021, MSRV 1.82 (declared in the workspace `Cargo.toml`; enforced by CI).
- License: **MPL-2.0**, matching upstream. Every source file carries an
  `SPDX-License-Identifier: MPL-2.0` header.
- The crate `version` tracks the pinned upstream Prism release.
- New pinned third-party versions (crates or GitHub Actions): record the version
  **and its license** (see the note in the workspace `Cargo.toml` and `ci.yml`).
- `#![deny(missing_docs)]` is on for `prism-types` and `prism`; document public items.
